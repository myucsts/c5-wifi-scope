# シリアル通信の仕様(ファームウェア ⇔ ブラウザ)

ボードとブラウザは、USBシリアルで **改行区切りのテキスト** をやり取りします。
ボードから来る行は、1行が1つのJSONです。`{` で始まらない行(起動ログなど)は無視してください。

## ボード → PC

| `t` | 意味 | フィールド |
|---|---|---|
| `hello` | 現在の設定(接続時、命令を受けるたび、起動時) | `id`(個体ID 16進4桁), `band`(`2`/`5`/`a`/`n`), `dwell`(ms), `scan`(0/1), `chans`(指定チャンネル数。0は通常巡回) |
| `ch` | 1チャンネルぶんの受信集計 | `ch`, `n`(フレーム数), `b`(バイト数), `avg`/`max`(RSSI dBm), `ms`(実際の滞在時間) |
| `ap` | AP情報 | `ssid`, `bssid`, `ch`, `rssi`、ビーコン由来なら `w`(幅MHz)と `c`(中心チャンネル番号)、スキャン由来なら `auth` |
| `m` | 測定結果(`mstop` のとき、APごとに1行) | `ssid`, `bssid`, `ch`, `w`, `n`(聞いた回数), `avg`(dBmの平均), `max` |
| `mdone` | `mstop` の出力の終わり | なし |

- `bssid` は大文字の `AA:BB:CC:DD:EE:FF` 形式です。
- `w` と `c` は、ビーコンのHT Operation / VHT Operation から読んでいます。ビーコンを受信できたAPだけに付きます。
- 5GHzの `c` は、チャンネル番号と同じ5MHz刻みの番号です(80MHz幅で36〜48なら `42`)。

## PC → ボード

| 命令 | 内容 |
|---|---|
| `band 2` / `band 5` / `band a` | 巡回する帯域(2.4GHz / 5GHz / 両方) |
| `band n` | 巡回せず、APスキャンだけを続ける |
| `dwell <ms>` | 1チャンネルの滞在時間(30〜1000) |
| `scan 0` / `scan 1` | 定期的なAPスキャンのオフ / オン |
| `scannow` | すぐにAPスキャン |
| `chans 1,6,36` | 巡回するチャンネルを指定(最大40)。`chans all` で解除 |
| `mstart` | ビーコンのRSSI集計を始める(指定チャンネルで聞こえた分だけ数える) |
| `mstop` | 集計を止めて、結果(`m` 行と `mdone`)を出力する |
| `ident` | 3秒間、LEDを速く点滅する |
| `hello` | 現在の設定を返す |

`mstop` 以外の命令は、実行後に `hello` を返します。

## 巡回するチャンネル

- 2.4GHz: 1〜13
- 5GHz: 36〜64、100〜144、149〜165(日本向け。設定できないチャンネルは自動で飛ばします)
